# Daily Focus architecture

## Boundaries

`src/domain/` owns the data types, validation, time rules, item actions, card selection, and action reducer. Domain functions receive `now` when they need the current time. They return data and do not read browser storage.

`src/store/` owns persistence, cross-tab updates, subscriptions, and the React hooks that read or dispatch app data. Components do not access `localStorage`.

## Data model

`AppData` is a version 1 document with items, `{ habits, tasks }` order, session history, daily marks, skipped days, per-item clocks, the active run, the pinned card item, settings, metadata, and deletion tombstones. New items and session records use `crypto.randomUUID()`. The parser ignores legacy group fields so existing data and backups load as standalone items.

`Item` is a discriminated union on `kind`:

- A `habit` has scheduled weekdays.
- A `task` has no schedule.
- A `quick` item is a time item with no goals, a fixed session number, and the day it started. Its name may be empty; `displayName` then returns `Session {number}`.

All item kinds have `id`, `name`, `completion`, `goals`, `createdAt`, and `updatedAt`; time items can have a `timerStyle`. Completion is `'check' | 'count' | 'time'`; timer style is `'sessions' | 'free'`; timer phase is `'focus' | 'break' | 'long-break'`. `DayKey` is a local `YYYY-MM-DD` date after the configured day-start hour. Weekday indexes start at Monday, `0`.

Goals store `{ from, target }` entries, so a change applies from its day forward. Check items and quick items have no goals. A `DayMark` stores `itemId`, `day`, `count`, `done`, and `updatedAt`. A `Session` stores `id`, `itemId`, `day`, `startedAt`, and `durationMs`. `ItemClock` stores `style`, `phase`, `round`, `elapsedMs`, and `day`. `Run` stores `itemId`, `startedAt`, and the clock snapshot used to derive live elapsed time.

Settings contain `dayStartHour`, `weekStart`, `skipsPerMonth`, and `updatedAt`. Metadata contains `firstUseAt`, `lastExportAt`, `bannerDismissedAt`, `autoStop`, `columnsOpen`, `quickStyle`, and `lastQuickNumber`. Tombstones map deleted item IDs to deletion timestamps.

## Card and quick-session lifecycle

`cardItem(data, day, now)` selects the running item first. With no run, it selects a pinned time item that is not done today. Otherwise it selects the first scheduled, unfinished time habit in habit order, then the first unfinished time task in task order. It returns `null` when none qualifies.

`openApp(data, now)` settles a run left active. It keeps a pinned quick item, but clears any other non-null pin. This lets a paused quick session remain on the card across reloads while a saved task returns to normal selection.

`newQuickSession` pauses any active run, creates and pins a quick item, and advances `meta.lastQuickNumber`. It starts the new item only when requested. A style change resets that item's clock; if it was running, the change logs elapsed focus time and starts it again. Starting another item ends the pinned quick session by removing its saved clock, while its item and logged sessions remain.

`saveQuickAsTask` names the task after the session (`Session {number}` when the name is empty) and changes the same item ID to `kind: 'task'`. It adds a 30-minute goal from the current day and appends the ID to task order, so its session history stays attached. A pinned item keeps its pin and clock. An unpinned item loses its quick clock; its task clock is created when it next starts.

## Timer behavior

Timers store timestamps, not ticking totals. `currentClock` derives the live elapsed time from `Run.startedAt` and its saved clock. Pausing writes focus-time `Session` records, split across configured day boundaries, and saves the clock. Break time does not create sessions. Session-style timers stop at phase boundaries; free runs stop at the 12-hour cap. `useNow(intervalMs)` only triggers display updates.

`PhaseAlerts`, mounted in `App` after `<main>`, owns the one-shot phase-end timeout. It dispatches `settle` at the next interval end plus 50 ms. It also dispatches `settle` on `visibilitychange` (when the page becomes visible), `pageshow`, and window `focus`, so a phase that ended while the page was hidden settles on return. `settle` leaves the data unchanged when no run is due.

## Timer alerts

When a focus session or break ends, `PhaseAlerts` shows a toast on every page. The other channels depend on the case:

| Event                                                                                                                    | Toast                                                                       | Chime          | OS notification                                  |
| ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- | -------------- | ------------------------------------------------ |
| Phase ends while the window has focus                                                                                    | Interval-end message, default duration, such as "Focus 1 done. Break next." | If Sound is on | None                                             |
| Phase ends while the window is in the background (`document.hasFocus()` is false), detected within 60 seconds of the end | Same toast                                                                  | If Sound is on | If Notifications is on and permission is granted |
| Phase end detected more than 60 seconds late                                                                             | "Focus 1 ended at 10:25 AM. Break next.", stays until dismissed             | None           | None                                             |

Hidden-tab timers in Chrome and Firefox fire about 1 second late, so a delay of more than 60 seconds means the page was paused, asleep, or closed. A chime or notification that late would confuse the user, so the late case shows one persistent toast with the end time. The threshold compares `Date.now()` with the phase end time (`startedAt` plus the phase duration, minus elapsed time, as in `phaseEndOf`).

The load path covers a phase that ended while the app was closed. `createStore` runs `openApp` on the stored data and calls `phaseEndOf` between the stored and settled documents. It keeps the result, and `takeMissedPhaseEnd` returns it once and then `null`, so the second effect run in React StrictMode does not alert twice. `PhaseAlerts` takes the value on mount and applies the same 60-second rule as a live end. A reload within 60 seconds of the end gets the standard toast and the notification path. Audio is locked on a fresh load, so no chime plays until the user presses a key or the pointer.

Sound and notification preferences are per browser. They live in `localStorage` under `daily-focus:soundEnabled` (Sound is on unless the stored value is `'false'`) and `daily-focus:notificationsEnabled` (Notifications are on only when the stored value is `'true'`). They live outside `AppData` because notification permission belongs to one browser profile, and storing the switches in `AppData` would carry them into backups and merges.

Several tabs can open the same data, so each phase end is claimed once. `claimAlert(id)` writes the id `${itemId}:${endedAt}` to `localStorage` under `daily-focus:lastAlert` and returns `false` when that id is already stored. The first tab to claim an end plays the chime and shows the notification. Every tab still shows the toast.

The notification is created from the page with `new Notification`, so the service worker has no alert code. It uses the item's display name as the title, the interval-end message as the body, the tag `daily-focus-phase-end`, and `/pwa-192x192.png` as the icon. It is shown only when the window is not focused and permission is `'granted'`. Clicking it focuses the window and closes the notification. Errors from the constructor are caught.

The chime is a synthesized completion melody from Web Audio, about three seconds long: one rising C major arpeggio (C5, E5, G5, C6, 0.16 seconds apart), then a C5, G5, C6, E6 chord at 1.2 seconds, after a pause of 0.72 seconds past the last arpeggio note, that rings for 1.6 seconds. Each note is a sine fundamental plus a quieter octave overtone, with a 0.01-second fade-in and an exponential decay. No audio file is loaded. The first `pointerdown` or `keydown` on the window calls `unlockChime`, which creates or resumes the shared `AudioContext`. Turning the Sound switch on in Settings plays the chime once through `previewChime` so the user hears what they will get. `playChime` does nothing until the context is running.

While a run is active, the tab title is the clock, the phase label, and the site title, for example `24:59 Focus | Daily Focus`. Session phases count down and use the labels Focus, Break, or Long break. A free run counts up and uses the item's display name as the label. With no run, `useSeoMeta` sets the page title and `PhaseAlerts` leaves it alone.

Alerts are best effort. Browsers can pause or discard hidden tabs (Edge sleeps hidden tabs after 15 minutes by default, Safari can suspend background tabs, and Chrome Memory Saver can discard idle tabs). The app has no push server, so nothing runs while the app is closed. The return toast covers the gap.

The Settings page has an "Alerts" section (`AlertSettings`). It holds a Sound switch and a Notifications switch. Turning Notifications on calls `requestNotificationPermission`, and the switch stays off unless the permission is granted. When permission is denied, a message explains how to allow notifications in the browser's site settings. Browsers without `Notification` show a line saying so in place of the switch.

## Persistence and sync

`createStore` reads `daily-focus:data`. If the key is missing, it starts with `emptyData(now)`. Otherwise it parses the JSON and calls `openApp`. When loaded data has a run and `openApp` changes the document, the store writes the settled document back and requests persistent browser storage.

Invalid stored data is copied to a unique `daily-focus:data:corrupt-<timestamp>` key, the main key is removed, and the store starts empty with an error. Dispatch runs the reducer with the current time. If data changed, the store writes the whole document, updates subscribers, and requests `navigator.storage.persist()` once when available.

A `storage` event for the document key replaces in-memory data after validation and notifies subscribers. A removal or clear event resets the store to empty. Invalid data from another tab leaves the current document intact and reports an error. Since the active run is part of the shared document, a change in one tab is reflected in the others.

`AppDataProvider` supplies the store. `useAppData` selects data through `useSyncExternalStore`; `useDispatch` returns the store dispatcher, and `useAppError` reads its error. `useNow` provides the display clock without changing stored timer state.

## Offline and install

`vite-plugin-pwa` (configured in `vite.config.ts`) turns the build into an installable, offline-capable app.

- **Service worker:** the default `generateSW` strategy emits `dist/sw.js` and a Workbox runtime file. The plugin injects the registration script into the built page, so no component registers the worker.
- **Updates:** `registerType: 'autoUpdate'` installs a new worker as soon as it is available and reloads open tabs onto it.
- **Offline navigation:** the build precaches all emitted assets, and `navigateFallback: 'index.html'` serves the app shell for any route while offline.
- **Google Fonts:** `fonts.googleapis.com` stylesheets use `StaleWhileRevalidate`. `fonts.gstatic.com` font files use `CacheFirst` with statuses `[0, 200]` and a one-year expiration.
- **Manifest:** the plugin emits `dist/manifest.webmanifest` from the `manifest` option. The app is named "Daily Focus", starts at `/`, and opens in `standalone` display mode.
- **Icons:** `public/pwa-192x192.png` and `public/pwa-512x512.png` are listed with purpose `any`. They come from the FBOW filled favicon artwork. `favicon.svg`, `favicon-32x32.png`, and `apple-touch-icon.png` cover browser tabs and iOS.
- **Theme color:** `#0e1515` is Kestrel's `--gray-90` token (`src/styles/colors.css`). It is the manifest `theme_color` and `background_color`, and the `theme-color` meta tag in `index.html`. Keep the three in sync.

## Shared utilities

- `src/utils/format-duration.ts` exports `formatDuration(minutes)`, which writes a duration as "25 min", "2 h", or "1 h 35 min". `week-stats.tsx` converts milliseconds to minutes before calling it.
- `src/utils/count-label.ts` exports `countLabel(count, noun)`, which writes "1 item" or "3 items". `import-dialog.tsx` and `backup-settings.tsx` use it.
- `src/utils/format-clock.ts` exports `formatClock(totalSeconds)`, which writes a clock as `M:SS` or `H:MM:SS`. The focus card and the tab title use it.
